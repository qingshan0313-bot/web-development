已准备的运行方式
• npm run dev：直接运行 src，本地默认 127.0.0.1:4173，修改后刷新。
• npm run build：构建 dist。
• npm run preview：预览构建后的 dist，本地默认 127.0.0.1:4174。
• npm start：自动构建，然后运行生产静态服务；监听 0.0.0.0:$PORT，默认端口 8080。
• AI Studio 预览若要求容器监听所有网卡，可运行 npm run dev -- --host 0.0.0.0；端口使用平台提供的 PORT，或用 --port 指定。
• ProRes MOV 必须通过本地 HTTP 或部署后的 HTTPS 页面使用 Worker；双击 file:// 页面不能导出 MOV。MP4/WebM 可在浏览器支持时继续通过 file:// 体验。

后续导入与发布
1. 将这个文件夹的内容放到 GitHub 仓库根目录，确保根目录能直接看到 package.json、server.mjs、build.mjs 和 src/。
2. 在 Google AI Studio 的 Build 模式中，从输入框的 Add files（+）菜单选择 Import from GitHub，导入该仓库。
3. 在 AI Studio 中运行并确认预览、文件选择、下载、时间线拖动、批量混剪及视频导出。嵌入式预览若限制下载或 Worker，应再到独立页面确认。
4. 准备上线时使用 Publish。AI Studio 的发布服务运行在 Cloud Run，具体账号条件按发布页面提示处理。
5. 部署后在实际网址验收；不要只验证本地文件模式。

供 AI Studio 继续编辑时使用的说明
这是已有的 Frame 素材工具台，请保留现有黑白主调、蓝色点缀的 UI，以及十一个工具和动画时间线。
十一个工具为：视频居中、批量混剪、批量重命名、智能命名、字幕编辑、对话打字动画、数字计时器、选项动画、相纸图、对话气泡、图片取色。
保留首页「工作台」的加大四格图标、顶部 QS STUDIO、页脚 11 个工具、分类缓动与子工具高亮。「批量制作」为独立分类，包含批量混剪；「智能命名」位于素材与效率。首页「开始创作」滚到工具列表，顶部 QS STUDIO 返回总览并保留分类展开状态。点击左上角「Frame 素材工具台」平滑滚回首页顶部并显示主图。
请继续运行和修改现有代码，保持当前工具功能。应用使用原生 ES Modules 和 Node.js 静态服务，无需 npm 安装运行依赖；本地内置 Mediabunny 1.66.0 和单线程 FFmpeg WebAssembly，运行时不使用 CDN。
源文件在 src；构建命令 npm run build；生产启动命令 npm start，兼容平台注入的 PORT。
对话动画使用「台词顺序／画面键盘／导出文件」三个标签页，支持台词增删、排序、批量粘贴、每句停留、背景图和颜色设置。
左侧对方消息直接显示完整气泡，仅右侧自己消息逐字输入。对方消息不占用打字时长；最后一句保留输入框仅对自己消息生效。
保留九宫格／QWERTY／隐藏键盘、语言选择和键帽提示；中文键盘是视觉演示，不含拼音输入法或联想候选词。
英语模式使用英文 QWERTY，输入框、发送按钮及键盘标签为英文；字母、空格、数字及常见标点按实际字符高亮。自动模式以自己的台词判断输入语言，对方消息保持直接出现。
时间线预览、完整视频导出和当前帧 PNG 共用同一画面模型。对话输出支持 720×1280／1080×1920、24/30/60 fps；MP4/WebM 支持 4/6/12 Mbps，ProRes MOV 使用固定质量。
视频居中、批量混剪、对话打字动画、数字计时器、选项动画五个视频工具均默认 MP4，支持切换 MOV 或 WebM。对话草稿与项目 JSON 保存 outputFormat、transparentBackground、台词、其他参数和压缩背景图，可导入后继续编辑。
MP4 使用 H.264，有声输入使用 AAC；MOV 使用 ProRes 4444 并保留 Alpha，有声输入使用 PCM。动画的 MP4/MOV 按固定帧率逐帧生成；动画 WebM 实时录制，三个动画工具均无声。
三个动画工具在 MOV 模式下默认开启透明背景，可关闭。对话透明模式跳过全画布背景色和背景图，但键盘、气泡、头栏自身底色保持不透明；关闭开关恢复背景设置。预览棋盘格不写入导出文件，PNG 保存真实透明度。
视频居中默认透明留边，保留原视频画面；已有视频不会自动抠像，不能将不透明的源画面直接变为透明。
MP4 导出检测浏览器 WebCodecs/H.264 和必要的 AAC 编码能力，推荐新版 Chrome / Edge；不支持时提示改选 WebM。
MOV 编码组件在本地单线程 Worker 中运行，必须使用 HTTP/HTTPS，不能在 file:// 页面运行。FFmpeg wasm 约 31 MiB，随本站 vendor/ffmpeg 加载；无需 COOP/COEP 跨源隔离响应头，不应误改成需要 SharedArrayBuffer 的多线程构建。
ProRes 文件较大，长片段和高分辨率会增加耗时及内存占用。逐帧 PNG 输入缓存累计上限 256 MiB，超过时明确提示缩短片段或降低分辨率；其余输入/输出超限也应保留现有错误提示。

批量混剪的已实现范围
两组本地多文件素材分别作为片头和成片；每个素材可选中、删除、设置起止秒数和 0–2 倍音量。
支持单片头 × 多成片、全组合、数量相同的顺序配对。输出画幅为 720×1280、1080×1920、1280×720、1920×1080 或 1080×1080，另有 24/30/60 fps、contain/cover、背景色、码率档和命名前缀。
加入队列时保存素材裁剪、音量和输出设置快照；修改左侧设置不回写已有队列。最多 50 条待处理任务，队列支持勾选、移除、逐组合预览和处理状态。
批量顺序执行；某条失败后继续下一条，并保留失败原因。单个成功结果直接下载，多个成功结果打包 ZIP；取消不自动下载未完成批次，但已完成结果仍可单独或打包下载。
素材文件、队列与生成结果只保留在当前标签页会话中，切换工具仍保留，刷新或关闭后丢失。制作记录使用独立 localStorage key，最多保留 500 条、显示最近 50 条，支持标为完成、删除及 JSON 导入导出。
默认去重依据为源文件名/大小/修改时间及裁剪、音量、输出参数，未计算文件内容哈希；文件名前缀不参与去重。不要将它描述为内容哈希校验。可关闭去重重新生成。
记录不包含媒体文件，也不是云端备份；已生成/已完成不证明文件已下载，长期保存必须下载结果。
不扩展 AI 自动剪辑、报表或云端团队服务。

智能命名的已实现范围
入口在素材与效率，路由 #smart；多选导入图片或视频，本地读取元数据和缩略图，视频按时间均匀抽取 8 帧用于 AI。支持 16 个命名字段、统一修改、手动字段保护与解锁、字典选项增删及标签说明、模板/日期/缩写/序号设置、逐条最终名称覆盖和单独下载、所选 ZIP、全列表 CSV、按日期记录下载后的续排序号。
保留原站字段代码，未知内容不要自动猜默认国家、性别或产品。AI 只识别画面，失败继续、可取消与重试，异步结果不能覆盖用户手改字段。取消后已完成结果保留。文件和结果只在当前标签页会话保留，页面刷新后需重选。
AI 默认 Base URL 为 https://ark.cn-beijing.volces.com/api/v3，模型 ID 留给用户按账号配置，不把原站 Agent Plan 模型别名硬编码为可用默认。接口需兼容 Chat Completions 并支持多图输入。图片和字段选项以数据处理，不执行画面中的指令。

数据与服务边界
媒体加工、元数据读取、手动命名和 ZIP 打包在浏览器中完成。本地收藏、对话草稿、命名配置及混剪记录不跨设备/网址同步。当前版本不需要数据库和登录。
智能命名由用户提供视觉模型 API Key 和模型 ID，默认只在当前页面内存使用 Key；用户可主动选择记住或清除。仅在用户允许并点击分析后发送抽帧图片，不发送原视频和音频。服务端不落盘、不记录请求正文或密钥，部署日志也应保持这一约束。
server.mjs 的 /api/capabilities 告知同源转发能力；POST /api/smart/analyze 由 smart-relay.mjs 处理，仅接受同源请求及火山官方域名下两个明确的 chat/completions 路径，拒绝重定向和任意代理目标。不要移除来源检查、体积限制、超时与取消处理。
使用纯静态托管时没有本应用转发，AI 会直接请求用户配置的接口，需服务允许浏览器跨域。完整 Node 服务部署则支持火山同源转发。未启用 AI 时所有命名和导出功能均可离线使用。

源码与构建交接
src/app.js 提供工具目录、共享界面和时间线；chat-model.js 管理项目与时间轴，chat-renderer.js 绘制画面，chat-ui.js 管理对话编辑与导入导出，chat.css 提供编辑器样式。
media.js 提供下载、图片、ZIP 和 WebM 录制；video.js 负责视频合成；video-export.js 统一输出格式、MP4/H.264 编码及视频转换。
mix-model.js 校验混剪设置、配对、去重和记录；mix-ui.js 管理素材、队列快照和批量操作；mix-preview.js 提供原声衔接预览；mix.css 仅作用于混剪编辑器；video-join.js 执行两段视频裁剪拼接与音频处理。
video-export.js 将 MOV 分派到 prores-export.js；后者管理本地 Worker、ProRes 4444/Alpha、PCM、取消和资源清理。
smart-model.js 管理命名字段、原站缩写选项、模板、手动字段保护与安全输出名；smart-media.js 读取素材与抽帧；smart-ai.js 调用视觉模型并检测同源转发；smart-ui.js 和 smart.css 提供统一编辑页面。smart-relay.mjs 必须随 server.mjs 一起保留，供 Node 本地和生产服务加载。
src/vendor 包含 Mediabunny 及 src/vendor/ffmpeg 下的 FFmpeg wasm、加载脚本和 Worker；所有组件版本、许可证和对应源码来源以 THIRD_PARTY_NOTICES.txt 及随附许可证为准。
修改 src 后运行 npm run build，统一生成 dist 并复制 vendor，不手工修改构建输出。发布和分发时必须保留 dist/vendor 的库与许可证。
源码交接保留完整 src、build.mjs、server.mjs、smart-relay.mjs、package.json、THIRD_PARTY_NOTICES.txt 和说明文件，不只提交单个 HTML。

在独立 HTTP/HTTPS 页面验收 FFmpeg Worker 和 wasm 加载、取消清理，以及 file:// 导出 MOV 时的明确提示；确认完整 vendor/ffmpeg、Mediabunny 和许可证随发布文件保留。
